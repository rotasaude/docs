# ADR 0010 — CQRS: projections & snapshots

- **Status:** Aceita
- **Data:** 2026-06-23
- **Contexto:** Rota Saúde

## Decisão

Quando uma triagem termina, dois artefatos de leitura com **fontes da verdade
diferentes** são produzidos: um **`ReportSnapshot`** congelado e imutável — o
relatório individual do cidadão, que é prova do que aconteceu — e
**`DashboardMetric`** agregado e reconstrutível — os painéis da secretaria, que
convergem para a verdade dos fatos mesmo que algum agregador falhe. Os dois caminhos
são desacoplados: falha em um não afeta o outro.

## Detalhamento

**`ReportSnapshot` — congelado, imutável.** Após `triage.completed`, o
`GenerateReportJob` cria um snapshot que congela:

| coluna | tipo | nota |
|---|---|---|
| `triage_id` | uuid | — |
| `protocol_definition_id` | uuid | versão exata usada (ADR 0009) |
| `outcome` | jsonb | `Outcome.to_h` — tier/priority/trail |
| `payload` | jsonb | resposta human-readable (templates já aplicados) |
| `token` | string | url-safe, único, indexado |
| `signature` | string | HMAC do token com `REPORT_SIGNING_KEY` (ADR 0013) |
| `expires_at` | timestamptz | expira o link sem deletar o dado |

O `payload` é congelado: mesmo que o template ou o protocolo mudem amanhã, o que o
cidadão vê em `GET /r/:token` é o que foi gerado hoje. O `token` + `signature` evitam
varredura — a rota verifica o HMAC **antes** de buscar no banco, checa `expires_at` e
renderiza o `payload`. É o único endpoint público.

**`DashboardMetric` — agregado, reconstrutível.** Linhas pré-agregadas por
`(municipality_id, dimension, period, key, value)`. A atualização **incremental** vem
do `UpdateDashboardJob`, consumidor de `triage.completed`, que faz
`INSERT … ON CONFLICT … DO UPDATE` em poucas linhas, sem locks longos. A
**reconstrução completa** vem de um script noturno que trunca as linhas, lê tudo de
`triages` (a fonte da verdade), recalcula e insere em batch. É esse rebuild que
garante a convergência das métricas para os fatos, mesmo que um `UpdateDashboardJob`
tenha falhado, sido reenfileirado ou ficado fora de ordem.

**Notificação e alerta.** O `NotifyCitizenJob` consome `triage.completed`, busca o
snapshot, monta a URL assinada e enfileira o `SendWhatsappJob` (ADR 0005/0007). O
`AlertMunicipalityJob` consome `triage.urgent` na fila `urgent` (ADR 0006) e entrega
ao destinatário configurado por cidade (ADR 0013). Ambos são idempotentes (ADR 0005).

Sob RLS (ADR 0003), `report_snapshots` e `dashboard_metrics` são escopadas por
política; a visão agregada cross-tenant do operador roda sob bypass com
`GROUP BY municipality_id`. As tarefas recorrentes (rebuild noturno, purga de
relatórios expirados, purga de `processed_events`, reconciliação de consentimentos)
vivem em `recurring.yml` (ADR 0014).

## Invariantes

- O `ReportSnapshot` é **imutável** depois de criado — é prova, não interpretação
  atualizada. Para "corrigir" um relatório errado, expira-se o token e gera-se um
  snapshot novo.
- O `payload` é congelado: o que o cidadão vê não muda quando o protocolo muda.
- O `DashboardMetric` é **reconstrutível**: o rebuild converge para a verdade dos
  fatos; nunca se edita métrica à mão.
- Triagens `aborted_by_revocation` não contam como "completadas" (ADR 0008).
- O HMAC do token é verificado **antes** do lookup no banco.

## Consequências

- O relatório individual atende auditoria e responsabilização clínica — é prova do
  que aconteceu, não interpretação atual.
- A corrupção de métricas tem cura óbvia: rodar o rebuild, sem precisar entender o
  que falhou.
- Duplicação aceita: o dado existe cru em `triages` e agregado em `dashboard_metrics`
  — porque a reconstrução é trivial.
- O `payload` precisa caber em jsonb com performance razoável (~10 KB); protocolos
  com trail longo podem precisar de poda **no payload**, nunca no `outcome.trail`.

## Relacionado

- ADR 0003 — RLS escopa as projeções; agregado cross-tenant sob bypass.
- ADR 0004 — consome `triage.completed` e `triage.urgent`.
- ADR 0005 — jobs idempotentes; envio fora do lock.
- ADR 0006 — fila `urgent` do alerta; `housekeeping` das purgas.
- ADR 0009 — o snapshot congela o `Outcome` e a versão exata da definição.
- ADR 0013 — `REPORT_SIGNING_KEY` e o destinatário de alerta por cidade.

## Em aberto

- Extrair o `payload` para object storage se o snapshot crescer além do confortável
  em jsonb.
- Fatias do dashboard por médico/posto — adicionar `key` composto ou tabela
  específica, conforme o brief do dashboard da cidade.
